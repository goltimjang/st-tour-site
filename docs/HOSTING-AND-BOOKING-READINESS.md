# 운영 호스팅·견적 관리 연결 준비

2026-09-24. 현재 구현은 정적 웹사이트다. 이 문서는 연결 계획이며 아직 서버·회원·예약·결제가 설치됐다는 뜻이 아니다.

## 현재 바로 옮길 수 있는 범위

`npm ci && npm run build` 결과의 `out/`을 정적 파일 배포를 지원하는 상업용 호스팅에 올릴 수 있다. 기존 도메인, trailing slash URL, canonical, 광고 랜딩 주소를 유지한다. GitHub 저장소는 소스 관리로 계속 사용한다.

호스팅 제공자·프로젝트 소유 계정·요금제·도메인 관리 접근이 확인되면 미리보기 배포부터 진행한다. 현재 계정 연결이나 결제 약정은 만들지 않았다. 기존 GitHub Pages 자동 배포는 임의로 삭제하지 않았다.

전환 순서:
1. 대상 호스팅의 미리보기에서 전체 경로, 새로고침, 404, 리소스와 URL 앵커를 확인한다.
2. 실제 문의 1건은 사용자 승인 후 메일 도착까지 확인한다. FormSubmit의 호스팅/도메인 허용 및 활성화 상태를 점검한다.
3. GA4 ID가 제공되면 빌드 환경 변수 NEXT_PUBLIC_GA4_ID로 연결하고 실제 수집을 검증한다. 네이버 광고 전환 코드는 별도 계정 정보와 이벤트 정의가 필요하다.
4. 승인된 도메인 전환 시 DNS, 인증서, www/루트 리디렉션을 확인하고 이전 DNS·배포 버전으로 복귀할 수 있도록 기록한다.
5. 변경 후 robots.txt, sitemap.xml, canonical, 광고 URL, 견적 폼을 운영 도메인에서 다시 확인한다.

GitHub Pages 사용 제한 근거: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits

## 고객 견적·예약 화면에 필요한 실제 기반

정적 호스팅과 별개로 서버 API·DB·인증을 연결해야 한다. 임의의 데이터로 고객용 진행 상태를 표시하지 않는다.

최소 데이터: 문의 ID, 고객 식별자, 여행 조건, 담당자, 상담 상태, 견적 버전, 포함·불포함 비용, 유효기간, 공급자 확인 기록, 예약 상태, 동의 버전, 변경 이력. 공개 상품 정보와 고객 개인정보는 분리한다.

접수 순서: 입력 검증 → 서버에 문의 저장 → 접수 ID 응답 → 담당자 알림. 알림 실패 시 문의는 남아야 하고 재전송할 수 있어야 한다. 재시도에는 중복 방지 키를 적용한다.

인증·권한: 회원가입 없이 최초 문의 가능. 고객은 본인 확인 후 자신의 견적만 열람한다. 직원 권한을 분리하고 관리자 로그인 보호, 접근 기록, 백업·복구, 보유·삭제 절차를 구현한다. 추측 가능한 접수번호만으로 고객 정보를 공개하지 않는다.

상태 구분: 접수 / 상담 중 / 견적 전달 / 고객 검토 / 공급자 확인 / 예약 확정 / 취소. 실제 담당자 처리·공급자 확인 없이 다음 상태로 바뀌지 않는다.

동행자 공유: 공개 상품 링크 공유는 현재 구현했다. 개인 견적 공유는 별도 권한·만료·철회와 표시 항목을 정한 뒤 추가한다. 연락처·결제 정보는 기본 공유 항목에서 제외한다.

완료 판정: 고객 A가 B의 자료에 접근 불가, 메일 장애 중 문의 저장 유지, 재시도 중복 방지, 계정·자료 삭제 흐름, 운영자 변경 기록, 실제 고객과 담당자의 인수 시험.

## 앱 준비 상태

현재: 웹앱 manifest, 512px 아이콘, standalone 실행 설정, 저장한 상품 바로가기. 저장 기능은 현재 브라우저에 한정되며 기기 간 동기화는 없다.

추가 필요: 고객 견적/여행 데이터 연결, 필요한 공개 정보의 오프라인 제공과 만료 정책, 변경 알림 동의와 실제 발송 경로, 실기기 설치·복귀·외부 앱 이동 검증, 개발자 계정 및 스토어 심사 자료. 웹앱 메타데이터 추가를 스토어 앱 출시로 표현하지 않는다.
