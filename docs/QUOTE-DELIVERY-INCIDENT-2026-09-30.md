# 2026-09-30 견적 전송 장애

## 확인된 원인과 범위

- 사용자 승인에 따라 운영 사이트에서 점검용 이름·무효 전화번호로 실제 전송을 수행. 일반 고객 정보 재전송 없음.
- 22:24 KST 이후 관측: FormSubmit의 OPTIONS 사전 요청은 200, POST는 HTTP 500. POST 오류 응답에 CORS 허용 헤더가 없어 브라우저는 `MissingAllowOriginHeader / net::ERR_FAILED`로 표시한다.
- 해외 하노이 일정 미정, 국내 강원 당일/전화번호 하이픈, 하노이 공급 상품 일정 미정/이메일/항공 시간대, 로얄CC 고정 행사: 4개 운영 경로에서 동일한 500 오류 확인.
- 별도 로컬 진단 화면에서 최소 영문 필드 JSON, 폼 인코딩, 동일 수신 이메일 경로를 비교한 3건도 모두 500. 특정 새 필드나 한국어 상품 내용에만 발생하는 오류가 아니다.
- FormSubmit 공식 AJAX 도움말 자체에도 Server Error 500 내용이 나타남: https://formsubmit.co/ajax-documentation . 이는 지원 서비스 문제의 보조 근거이며 정확한 내부 장애 원인·복구 시간은 알 수 없다.
- 연결 Gmail의 스팸·휴지통 포함 검색에서 9/29 견적 수신 2건 확인, 9/30 점검 시 오늘 견적 및 테스트 수신 0건. 하루 전체 시도 횟수/손실 문의 건수는 서버 접수 로그가 없어 확인 불가.
- 이전 모의 접수 검증은 UI와 payload 검증이었다. 실제 외부 서비스 접수·메일 도착 증거로 사용하면 안 된다.

## 응급 보완

- 실패 화면에 고객이 작성한 요청 전체를 읽기 전용으로 표시. 내용 복사, 기존 카카오톡 채널, 기존 운영 이메일의 메일 앱 작성 링크, 전화 경로 제공.
- 복사/메일 앱 열기를 접수 성공으로 표시하지 않는다. 채팅·메일 앱에서 고객이 보내기를 눌러야 한다고 안내.
- 동일 내용 재시도는 같은 요청 참조번호 사용. 서버 중복 제거를 보장하는 기능은 아니며 담당자의 중복 대조용이다.
- 이메일 앞뒤 공백 정리, 전화번호 공백/하이픈 제거 후 전달. 입력 오류 및 필수 동의 검증 유지.
- 분석 도구가 예외를 던져도 견적 이동·실제 접수 결과를 방해하지 않게 분리.
- 외부 전송 서비스를 새 사업자로 변경하거나 개인 정보를 새로운 저장소에 전송하지 않았다. 개인정보는 기존대로 메모리에만 유지하며 브라우저 초안에는 저장하지 않는다.

## 남은 복구 조건

- 이번 프런트엔드 보완은 외부 HTTP 500을 해결하지 않는다. FormSubmit 복구 후 운영 폼에서 실제 테스트 1건을 전송하고 Gmail 도착까지 확인해야 자동 접수 복구로 판정한다.
- 장기 개선은 요청을 운영자가 관리하는 서버/DB에 먼저 저장하고 메일 발송을 재시도하는 구조. 현재 GitHub Pages 정적 호스팅에는 서버·접수 DB가 없다. 호스팅 및 개인정보 보관 장소를 확정해 별도 전환해야 한다.
- 고객이 창을 닫은 과거 실패 요청의 이름·전화·이메일은 저장하지 않았으므로 이 저장소에서 복구할 수 없다.
